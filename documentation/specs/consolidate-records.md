# Сведение материалов в общие факты

Контракт согласования фактов между источниками. Формат темы и записи факта выбирается по содержанию с сохранением устойчивых идентификаторов, оснований и истории исправлений.

## Назначение

`materials` хранит обработанное представление каждого источника. `records` сводит их в общую историю: факты и события, продолжающиеся измерения, темы, повторения и расхождения. Читатель темы получает актуально выбранные факты и открытые вопросы, не перечитывая каждую карточку.

Это отдельная операция после приёма. Группировка карточек в индексе материалов помогает найти источники, но не заменяет согласование фактов между ними.

## Результат

- Тематические представления в `records/topics/`, например эндокринология или кардиология; темы используют справочник областей материалов.
- Факты со стабильными идентификаторами, типом, медицинской датой, значением/единицей и точными основаниями. Один факт может входить в несколько тем без создания независимых копий.
- Ряды регулярных измерений в `records/measurements/`; тема ссылается на ряд, не переписывает всю таблицу отдельно.
- Для каждого существенного расхождения: варианты, источники, статус, выбранное значение при наличии, основание выбора и оставшийся вопрос. Решения по конкретным медицинским фактам хранятся здесь, а не в журнале архитектурных решений.

## Согласование

1. Определить, описывают ли записи одно событие: пациент, показатель/вид исследования, дата и образец/заявка, метод и единицы при наличии. Разные взятия, условия или времена не объявлять противоречием только из-за разных значений.
2. Объединить подтверждённые повторы ссылками на одно событие. Повторная печать, скан и запись сводки не создают повторное измерение.
3. Разделить ошибку чтения/ввода, различие единиц, разные события, разные версии заключения и подлинное неразрешённое расхождение. Не вычислять отсутствующие данные догадкой.
4. Для анализа предпочесть первичный документ. Если его нет — использовать ручную запись книги как сообщённое пользователем значение. Если ручное происхождение книги подтверждено пользователем, отсутствие первичного бланка само по себе не запрещает использовать такую запись.
5. Конкретно подозрительную клетку пометить отдельно. Дата Excel вместо результата не является пригодным числом анализа. Наличие опечаток в отдельных местах не дисквалифицирует всю книгу.
6. При доказанном выборе опубликовать рабочее значение и объяснение. Если оснований недостаточно — оставить вопрос открытым и показать варианты; не выбирать по большинству копий. Источники и прежние варианты сохраняются.
7. Новый первичный документ может подтвердить или заменить основание прежнего пользовательского факта, сохраняя связь с событием и историю исправления.

Приоритет документа для лабораторного числа не решает автоматически разногласие врачебных диагнозов или выбор лечения. Назначение, сообщение о фактическом приёме и расчётная доза — разные виды сведений. Медицинская интерпретация остаётся в `overview`/`outputs`.

## Практическая проверка

### События из нескольких источников

Читаемые материалы остаются самостоятельными источниками. Общая история использует
согласованные события, а не сумму строк выгрузок. У одного события могут быть
несколько представлений с разными ID, точностью и наборами показателей.

- Для каждой исходной записи сохранить источник и точный локатор. Подтверждённые
  представления связать с устойчивым ID одного события.
- Точный внешний ID может служить основанием связи. Без него проверять совокупность
  содержательных признаков, дат, известных зон и условий. Один день или похожее
  значение недостаточны. Допуски определять по проверенной точности источника.
- Неоднозначные совпадения сохранять кандидатами. Их влияние на итоговый охват
  показывать явно; не допускать скрытого двойного счёта или молчаливого исключения.
- Показатели согласуются отдельно от тождества события. Разные определения
  длительности, исходные и вычисленные величины не взаимозаменяемы. Варианты и
  основания выбора сохраняются; приоритет по имени сервиса не назначается.
- Каждая исходная запись связана с фактом либо имеет явную причину исключения.
  Подтверждённое событие учитывается один раз. Прикладную обработку агент создаёт
  после изучения фактических форматов и проверки правил на данных пользователя.

При необходимости используется [производная база](../../records/DATABASE.md).
Markdown темы и машиночитаемые факты не должны становиться независимо редактируемыми
копиями одной медицинской истории.

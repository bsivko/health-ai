# Проверки проекта

## Структура и ссылки

Из корня проекта:

```console
python -B scripts/check_project.py
```

Команда проверяет обязательные файлы и AGENTS.md основных слоёв, локальные
Markdown-ссылки и якоря, синтаксис Python, JSON и JSONL. Она ничего не изменяет.
Для проверки начальной пустой копии добавьте `--empty`.
Этот режим сверяет полный перечень и контрольные суммы файлов рабочих слоёв,
включая стартовые `AGENTS.md`, индексы и сводку приёма. При намеренном изменении
стартового содержимого сначала проверьте его, затем обновите эталонные суммы
в [скрипте проверки](../scripts/check_project.py). Проверка заполненного проекта
выполняется без `--empty`.

Перед публикацией чистого шаблона запустите `python -B scripts/check_project.py --empty --privacy`.
Флаг `--privacy` включает эвристический поиск путей, контактов, ключей и файлов
`.env` вне исключённых временных каталогов и окружений.
Результаты такого поиска требуют сверки по [правилам конфиденциальности](PRIVACY.md).

## Материалы и источники

```console
python -B scripts/materials.py verify
```

Проверяются реестр, классификация, SHA-256 оригиналов и зарегистрированных производных
файлов, области источников, соответствие идентификаторов и ссылок карточек реестру.
Команда также проверяет индекс и обнаруживает незарегистрированные карточки и
оригиналы. Для обновления индекса используется отдельная команда.

```console
python -B scripts/materials.py index
```

Проверка файлов не подтверждает медицинскую точность. Существенные числа, единицы,
даты и назначения сверяйте со страницами оригинала по контракту приёма.

## Учёт приёма

```console
python -B scripts/medications.py verify
```

Проверяются определения курсов, связи с материалами и допустимость сообщений.
Количество принятого меняется только по сообщению пользователя. Для чтения
состояния используйте status с явным `--as-of YYYY-MM-DD`.

## Изолированная проверка операций

```console
python -B scripts/smoke_test.py
```

В отдельной папке под temp проверяются приём вымышленных источников, запрет перезаписи,
обнаружение изменившегося источника, восстановление прерванного копирования,
поведение учёта приёма. Рабочие данные не изменяются.
Проверяются запоздалые сообщения, исправления и повторное завершение приёма после
сбоев записи реестра, одной из карточек и индекса. Незавершённая публикация должна
обнаруживаться verify; повторный accept не должен добавлять дубли.
Для проверки извлечения XLSX и поворота изображений добавьте `--formats`.
Для этого режима требуются зависимости из [requirements.txt](../requirements.txt).
Подробности: [примеры](../examples/README.md).

Не запускайте проверки с `-O`: часть скриптов использует assert. При сбое тестовая
папка остаётся для разбора; после успешного прогона удаляется только она.

## Расширение обработки

Для нового формата проверяйте полноту извлечения, неизменность оригиналов,
сохранность единиц, дат, локаторов и неопределённостей. Сначала проверьте подход
на небольшом понятном источнике. Ограничения конкретного материала храните в его
карточке; изменения рабочих возможностей — в CURRENT.md. Медицинскую обоснованность
результата нельзя подтвердить только программными проверками.

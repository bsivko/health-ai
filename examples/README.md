# Вымышленная демонстрация

Все значения, даты, названия и сообщения ниже придуманы для проверки механики.
Они не являются медицинскими данными реального человека или рекомендациями лечения.
Демонстрационные файлы не зарегистрированы в рабочих materials/records.

## Безопасный запуск

Из корня шаблона:

```console
python -B scripts/smoke_test.py
```

Скрипт создаёт отдельную копию каркаса в `temp/`, наполняет только её вымышленными
источниками, проверяет prepare/accept, контрольные суммы, запрет перезаписи,
обнаружение испорченных источников и поведение учёта приёма. Рабочие слои владельца
не копируются в тестовую папку и не изменяются. После успеха тестовая папка удаляется;
при ошибке путь остаётся в сообщении для разбора. Правила из AGENTS тест читает.

Не запускайте вымышленный приём прямо в рабочей истории. Для ручного изучения
создайте ещё одну отдельную копию пустого шаблона.

## Вход и приём в отдельной учебной копии

`demo-lab.txt` и `demo-product.txt` — явно вымышленные оригиналы с простым текстом.
`reviewed-intake.json` содержит предварительно сверенное представление, полную
таблицу, реквизиты, классификацию и точные SHA-256 этих файлов. Это учебный пример;
для реального документа содержимое и суммы готовятся после чтения самого источника.

В отдельной копии агент читает корневые и локальные AGENTS, затем:

1. Копирует эти два файла в incoming без изменения байтов.
2. Создаёт raw/2000-04-02 и materials/2000-04-02. В каждом создаёт и читает
   AGENTS.md с наследованием `../AGENTS.md`; карточки и оригиналы имеют зеркальные даты.
3. Копирует reviewed-intake.json в temp/reviewed.json и выполняет:

```console
python -B scripts/intake.py prepare temp/reviewed.json temp/receipt.json
python -B scripts/intake.py accept temp/receipt.json
python -B scripts/materials.py verify
```

`reviewed: true` допустимо только после действительной сверки. До accept оригиналы
остаются в incoming, карточки имеют статус ожидания. После успеха сверяются SHA-256,
реестр и индекс; квитанцию и свои промежуточные файлы можно удалить.

Сбой между копированием и удалением источника восстанавливается по той же квитанции,
если обе копии имеют ожидаемую сумму. Частично записанный или изменившийся архивный
файл останавливает операцию; источник не удаляется. Не перезапускайте prepare поверх
готовых карточек. До ручного исправления сохраните квитанцию и проверьте обе копии.
Сбой записи реестра, карточки или индекса также восстанавливается повторным accept
с той же квитанцией. Изменённый посторонней операцией реестр останавливает повтор.
Каждый файл публикуется атомарно, но обновление нескольких файлов не является
единой транзакцией: до успешного verify результат считается незавершённым.

## Примеры следующих слоёв

`measurement.json` — одно вымышленное пользовательское наблюдение. После проверки
его формата подобная запись относится к JSONL ряда по году наблюдения, а не к папке импорта.

`course.json` и `course-events.jsonl` — учебная схема и одно сообщение о принятом
количестве условного продукта DEMO. Его material_id вычислен из demo-product.txt.
Поля и ссылки здесь относятся только к изолированной учебной копии после приёма;
это не действующий курс владельца и не указание принимать препарат.
Проверка показывает, что на будущей дате количество не увеличивается и курс
не завершается автоматически. planned также не становится active по календарю.

`plot.json` — вымышленные точки с явным происхождением. В отдельной копии с Pillow:

```console
python -B scripts/plot_history.py examples/plot.json temp/demo.png
```

При отсутствии шрифта с кириллицей задайте `HEALTH_FONT` — путь к своему TTF.
Картинка не перезаписывается. Общие графики не извлекают данные и не согласуют
медицинские факты самостоятельно; подготовка и проверка входного JSON лежит на агенте.
